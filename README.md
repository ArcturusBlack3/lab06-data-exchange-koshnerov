## Контракт данных

CSV-заголовок: `id;date;customer;category;amount`. Пример:
`S01;01.09.2026;C01;Office;100.0`.
Это учебный CSV с `;`, без кавычек и многострочных полей, а не универсальный CSV-парсер.
В текстовых полях запрещены `;`, двойная кавычка, CR и LF. Обязательные строки
непустые, их регистр и пробелы не изменяются. Даты имеют четырёхзначный год.
CSV-сумма: неотрицательные десятичные цифры, необязательная дробь с точкой,
необязательная экспонента e/E с целым показателем; без пробелов и плюса перед суммой.
NaN, Infinity, переполнение до Infinity и отрицательные суммы запрещены; ноль разрешён.
Готовый Sale нормализует отрицательный числовой ноль JSON в обычный 0.

JSON: массив объектов с полями id/date/customer/category (строки), amount (число).
Все пять полей обязательны, null недопустим. Лишние поля игнорируются готовым mapper.
Синтаксис строгий: без комментариев и одинарных кавычек. Даты принимаются в обоих
форматах и экспортируются как ISO; сумма экспортируется числом. JSON создаёт Gson.
Не пишите свой JSON-парсер и не сериализуйте LocalDate через reflection.

Порядок и повторные id сохраняются в обоих форматах. Ошибка записи отклоняет весь
импорт без частичного результата. DataFormatException — ошибка содержимого,
IOException — ошибка файловой системы. У CSV-ошибки есть строка, у ошибки объекта
JSON — номер записи. Пустой CSV без заголовка ошибочен; один заголовок даёт пустой
список. JSON [] даёт пустой список. Экспорт пустого списка — заголовок CSV или [].

Готовые Checks оставить перед TODO. Проверить аргументы до открытия выходного
файла. Экспорт перезаписывает существующий файл; транзакционная/атомарная запись
при системном сбое не требуется. Данные небольшие, потоковая обработка больших
JSON-документов не требуется. Дубликаты ключей внутри JSON-объекта не рассматриваются.

## Работа в IntelliJ IDEA

1. Получите стартовый репозиторий через Get from VCS / File → New → Project from
   Version Control. Для архива: распакуйте и откройте папку с pom.xml через File → Open.
2. Выберите JDK 25 в Project Structure; дождитесь импорта Maven / Load Maven Changes.
3. Реализуйте только восемь TODO. Готовые модели, Checks, JsonSupport, Application,
   зависимости, тесты и data не изменяйте. Циклы и Stream API равноправны для отчёта.
4. Запускайте группу тестов зелёным треугольником. Все тесты: правый клик src/test/java
   → Run. В полностью выполненной работе проходят 80 тестовых сценариев.
5. Запустите Application.main зелёным треугольником. Working directory в конфигурации
   запуска — корень проекта (папка с pom.xml и data), обычно $PROJECT_DIR$.
6. Контроль: CSV: 10; JSON: 10; за период: 8; сумма: 1240.00; повторный импорт: по 8.
   Ожидаемый отказ для data/sales-invalid.csv указывает строку 2 и ошибку date.
7. Откройте output/period-sales.csv и output/period-sales.json, сравните записи.
   В IDEA при необходимости выполните Reload from Disk для обновления дерева проекта.
8. Commit → Git Log → Git → Manage Remotes → Git → Push в свой публичный репозиторий.
   Для архива сначала VCS → Enable Version Control Integration → Git.
   Не включайте target, output и .idea. Проверьте коммит в браузере.
